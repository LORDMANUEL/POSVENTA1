# v0.12.1 Certification and Module Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert the current `main` state into a certifiable Mily Zebra `v0.12.1` release, close real gaps in already-registered modules, and prove the enabled product with executable smoke tests.

**Architecture:** Keep one FastAPI/PostgreSQL source of truth, one React/PWA client, WebView2 as a wrapper, and a separate local hardware agent. Internal software-only modules must be operational and smoke-tested; external integrations (`payments`, `fiscal`, `music`, `visual`) remain fail-closed until real provider/physical certification exists.

**Tech Stack:** Python 3.13, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL 17, Redis 8, React 19, Vite 8, Node 24, Docker Compose, Playwright Chromium, Windows WebView2 launcher, Python hardware agent.

**Spec:** `docs/ROADMAP.md`, `docs/RELEASE_POLICY.md`, `docs/MULTITENANCY.md`, and the approved module roadmap discussed for `v0.12.1`.

## Global Constraints

- `main` must not be treated as stable until CI and Stable Gate pass on the same SHA.
- Historical upgrade baseline is `release/v0.12.0-rc1`, migration head `20260818_0009`.
- Candidate migration head is `20260819_0010`.
- Multi-tenant data isolation is mandatory for all business endpoints and local browser state.
- Stock, cash, returns, payments, fulfillment, reconciliation and print claims must remain concurrency-safe.
- Offline POS transactions must be durable and idempotent; no silent truncation.
- External provider/hardware modules must fail closed when not certified/configured.
- No new unrelated features enter this hotfix.
